# Content Format Rotator — Refatorando

## FUNÇÃO DA SKILL

Esta skill não serve apenas para listar formatos.

Ela deve atuar como um sistema de decisão criativa que responde:

1. Qual é a melhor lógica narrativa para este assunto?
2. Qual é a melhor forma visual de executar essa lógica?
3. O formato escolhido realmente melhora a compreensão e a retenção?
4. Existe outro formato menos óbvio que faria a ideia funcionar melhor?
5. Estamos repetindo uma estrutura usada recentemente?
6. O formato escolhido combina com o funil, com o CTA e com os assets disponíveis?
7. Há risco de o conteúdo parecer genérico, artificial ou visualmente repetitivo?

A skill deve ser usada antes da escrita final.

Ela complementa:
- Radar de Roteiros / pesquisa de tendências;
- análise de referências;
- Reels Scripting;
- Post Scorer;
- briefing criativo;
- direção visual.

Ela não substitui pesquisa factual, checagem de fontes ou validação de claims.

# PRINCÍPIO CENTRAL

Nunca escolher um formato apenas porque ele é diferente.

O formato deve cumprir pelo menos uma destas funções:

- aumentar clareza;
- melhorar retenção;
- tornar uma informação abstrata visual;
- aumentar identificação;
- gerar contraste;
- demonstrar algo;
- provar algo;
- criar progressão narrativa;
- facilitar compreensão;
- reforçar autoridade;
- reduzir aparência publicitária;
- aumentar intenção de ação.

Se o formato não acrescenta nenhuma dessas funções, ele é decoração.

# BIBLIOTECA DE FORMATOS NARRATIVOS

## Fofoca
Abrir como uma descoberta, bastidor ou informação que "você precisa ver".

Estrutura:
revelação → contexto → o que isso significa → consequência → CTA

Bom para:
novidades, mudanças de mercado, comportamento, bastidores, lançamentos.

Evitar:
sensacionalismo vazio ou transformar rumor em fato.

## Estudo fictício
Criar um cenário simulado claramente identificado como fictício.

Estrutura:
contexto → problema → dados → decisão → conclusão

Bom para:
Marketing, Vendas, Finanças, Liderança e IA aplicada.

Regra:
nunca apresentar como caso real.

## Use isso para isso
Relacionar ferramenta, recurso ou método a uma tarefa concreta.

Estrutura:
tarefa → recurso → demonstração → quando usar → limite

Bom para:
IA aplicada, produtividade, operação.

## Quadro branco
Construir a explicação visualmente.

Bom para:
frameworks, processos, relações, decisões.

## A + B + C
Explicar resultado como combinação de componentes.

Exemplo:
contexto + ferramenta + processo.

Evitar:
forçar tríades só por estética.

## Tela verde
Apresentador analisa um asset real ao fundo.

Bom para:
notícias, prints, gráficos, dashboards, interfaces.

## Talking head
Pessoa fala diretamente para a câmera.

Bom para:
opinião, autoridade, anúncio, reflexão.

Regra:
não usar por padrão quando outro formato deixa a ideia mais clara.

## Mindmap
Organizar tema complexo em ramificações.

Bom para:
ecossistemas, categorias, caminhos, áreas de aplicação.

## Ranking
Ordenar opções com critério explícito.

Estrutura:
critério → posições → justificativas → recomendação

## Tela na tela
Pessoa + captura de tela.

Bom para:
tutorial, análise, reação, demonstração.

## Musical
O ritmo visual e a música conduzem o conteúdo.

Bom para:
conteúdo leve, transições, resumo visual.

## Explicação ultra simples
Simplificar um conceito usando analogia e exemplo.

Estrutura:
conceito → analogia → exemplo → limite da analogia

Evitar:
infantilizar o público.

## Reunião
Representar dinâmica de trabalho.

Bom para:
liderança, vendas, conflitos, objeções, decisões.

## Caixinha
Responder uma pergunta real ou simulada.

Bom para:
FAQ, objeções, dúvidas frequentes.

## Erro comum
Mostrar erro, impacto e correção.

Estrutura:
erro → consequência → correção → exemplo

## Lista
Agrupar itens independentes sob uma promessa.

Bom para:
salvamento e utilidade.

## Cinemático
Narrativa conduzida por ambientação e B-roll.

Bom para:
manifesto, posicionamento, transformação, lançamento.

## Podcast
Conversação ou recorte com estética de conversa longa.

Bom para:
opinião, debate, autoridade.

## Stories nativo
Estética espontânea e menos publicitária.

Bom para:
remarketing, proximidade, atualização rápida.

## Depoimento
Experiência real.

Estrutura:
contexto → problema → experiência → mudança percebida

Regra:
não inventar resultado ou ampliar claim.

## POV
Colocar a audiência dentro de uma situação.

Bom para:
identificação, humor, dores de rotina.

## Vlog
Acompanhar sequência real de acontecimentos.

Bom para:
bastidores, evento, rotina, processo.

## Passo a passo
Tutorial linear.

Estrutura:
objetivo → passos → conferência → resultado

## Mito x verdade
Testar crença e explicar nuance.

Evitar:
reduzir questões complexas a falso/verdadeiro quando não cabe.

## Exercício
Pedir ação do público.

Estrutura:
desafio → instrução → critério → resposta

## Resposta
Responder diretamente a comentário, crítica, afirmação ou dúvida.

## Bastidores
Mostrar processo real, decisão, erro, preparação ou produção.

## Notícia
Explicar fato recente.

Estrutura:
o que aconteceu → fonte → contexto → impacto → aplicação

Regra:
separar fato, interpretação e opinião.

## Antes e depois
Comparar estado inicial e final.

Bom para:
processo, produtividade, organização, workflow, qualidade de saída.

Regra:
não fabricar resultado.

## UGC
Linguagem de criador/usuário.

Bom para:
anúncio, rotina, identificação, prova.

## Carrossel
Pode ser formato final ou lógica de sequência em vídeo.

## Clone
Uma pessoa interpreta dois ou mais papéis.

Bom para:
objeções, contraste, reunião, diálogo interno.

## Texto na tela
A narrativa é carregada principalmente por texto.

## Narrado
Voice-over sobre B-roll, interface ou sequência documental.

## Build in Public
Mostrar processo enquanto ele acontece.

Estrutura:
avanço → problema → decisão → próximo passo

## Cronômetro
Criar limite temporal real.

Bom para:
desafio, demonstração, eficiência.

Regra:
se o tempo for apresentado como prova, ele deve ser verdadeiro.

# FORMATOS ESPECÍFICOS DE CARROSSEL

## Editorial
Alterna texto, fotografia, print, dado e respiro visual.

Bom para:
análise, tendência, notícia, opinião.

Regra:
cada tela avança o raciocínio.

## Screenshot-first
A interface ou print é a evidência central.

Estrutura:
evidência → destaque → interpretação → aplicação

## Data Story
Narrativa construída a partir de dados.

Estrutura:
dado → contexto → comparação → implicação → conclusão

## Timeline
Organiza mudança ao longo do tempo.

## Comparativo
Avalia caminhos segundo critérios explícitos.

## Case Breakdown
Desmonta um caso.

Estrutura:
contexto → problema → decisão → execução → resultado/aprendizado

## Framework visual
Transforma raciocínio em modelo.

## Checklist visual
Conteúdo acionável de consulta rápida.

## Guia de decisão
Ajuda o público a escolher.

Estrutura:
se X → faça Y

## Manifesto
Sequência de afirmações que constroem posicionamento.

## Photo Essay
Fotografia participa da narrativa.

Regra:
imagem deve provar, contextualizar ou desenvolver a ideia.

## Documento anotado
Print, notícia, gráfico ou interface comentada visualmente.

## Interface Walkthrough
Percorre uma ferramenta ou fluxo.

## Notícia comentada
Combina fato + evidência + interpretação.

## Colagem de evidências
Combina 2–3 assets reais por tela.

## Tipografia protagonista
Texto conduz a composição.

## Full bleed + análise
Imagem ocupa a tela e o texto entra integrado à fotografia.

## Zoom progressivo
Começa por uma visão ampla e aproxima progressivamente de um detalhe.

## Narrativa documental
Usa prints, imagens, documentos, datas e registros para contar uma história.

Pontuar de 0 a 2 cada opção em:

Potencial de retenção:
Força visual:
Clareza:
Facilidade de produção:
Disponibilidade de assets:
Adequação ao funil:
Adequação ao CTA:
Adequação ao canal:
Originalidade dentro da marca:

Risco de depender de claim não comprovado:

Escolher a combinação com melhor equilíbrio.

Não escolher automaticamente a opção com maior "impacto" se ela piorar clareza ou exigir prova que não existe.

---

# DIVERSIDADE E ANTI-REPETIÇÃO

Antes de decidir, revisar os últimos conteúdos disponíveis.

Perguntar internamente:
- usamos esse formato recentemente?
- o gancho visual está parecido?
- a estrutura das telas está parecida?
- os assets estão parecidos?
- o ritmo está parecido?
- a CTA está sempre entrando do mesmo jeito?

Regras:

- não repetir talking head puro em mais de 2 vídeos consecutivos;
- em 5 vídeos, usar pelo menos 3 famílias de execução;
- em 5 carrosséis, evitar repetir a mesma arquitetura de telas em mais de 2;
- evitar sempre: capa → definição → lista → conclusão → CTA;
- variar entre conteúdo guiado por foto, print, dado, interface, tipografia, gráfico e narrativa;
- não escolher "carrossel editorial" como resposta automática para qualquer tema.

# REGRAS POR FUNIL

Priorizar:

## Meio
Priorizar:
explicação, demonstração, case breakdown, guia de decisão, passo a passo, estudo fictício, framework.

## Fundo
Priorizar:
prova, objeção, demonstração, depoimento real, UGC, antes e depois, stories nativo, resposta, produto em uso.

# REGRAS POR OBJETIVO

Se o objetivo for EDUCAR:
preferir demonstração, exercício, passo a passo, framework, quadro branco.

Se for GERAR SALVAMENTO:
preferir checklist, lista, guia de decisão, comparativo, framework.

Se for GERAR COMPARTILHAMENTO:
preferir identificação, POV, opinião, mito x verdade, notícia com impacto.

Se for PROVAR:
preferir evidência real, screenshot, dado, documento, demonstração, depoimento.

Se for VENDER:
preferir dor → prova → mecanismo → oferta → CTA, usando execução coerente com a etapa de funil.

Se for POSICIONAR:
preferir manifesto, análise, comentário de notícia, opinião fundamentada, comparação.

Antes de finalizar, especificar quais assets tornam o formato viável.

Exemplos:
- screenshot oficial;
- notícia;
- gráfico;
- interface;
- gravação de tela;
- foto real;
- vídeo oficial;
- comentário;
- depoimento;
- documento;
- dado;
- objeto contextual;
- professor;
- aluno;
- bastidor;
- tablet;
- quadro;
- ambiente de trabalho.

Priorizar asset real quando ele acrescenta contexto ou prova.

Evitar:
- imagem de IA usada apenas para preencher espaço;
- banco de imagem corporativo genérico;
- elemento tech decorativo sem função;
- cards dentro de cards;
- repetição de mockups sem necessidade.

# REGRA DE VARIAÇÕES PARA GRAVAÇÃO

Sempre que o roteiro trouxer múltiplas opções de abertura ou fechamento, todas as opções fazem parte do plano de gravação.

Objetivo:
- gerar variações de criativo sem regravar o desenvolvimento;
- testar diferentes ganchos;
- testar diferentes CTAs;
- adaptar a mesma peça para orgânico, anúncio ou remarketing;
- permitir edição posterior com combinações distintas.

Aplicação:
- gravar todas as aberturas;
- gravar todos os fechamentos;
- manter o desenvolvimento principal igual, salvo quando uma variação exigir adaptação;
- na edição, usar apenas uma abertura e um fechamento por versão final;
- se houver 2 aberturas e 3 fechamentos compatíveis, considerar até 6 combinações possíveis de versão;
- não tratar “opção A/B/C” como escolha prévia de produção.

# QA FINAL

Antes de entregar, revisar:

1. O formato ajuda o conteúdo ou só deixa diferente?
2. A narrativa combina com o objetivo?
3. O formato combina com o funil?
4. A primeira tela ou os primeiros 3 segundos têm força?
5. Existe progressão?
6. Cada cena/tela tem função?
7. Há informação repetida?
8. O visual participa do raciocínio?
9. Existe asset real que deveria substituir imagem genérica?
10. O CTA é coerente com a peça?
11. Existe claim sem prova?
12. A estrutura parece repetida em relação a conteúdos recentes?
13. É possível reduzir texto e aumentar comunicação visual?
14. O conteúdo continua claro sem depender de contexto externo?
15. Há uma execução mais simples que entregaria melhor resultado?

Se 3 ou mais respostas indicarem problema, reformular antes da entrega.

# PROMPT OPERACIONAL COMPLETO

Use este prompt quando quiser ativar a skill de forma explícita:

"Antes de criar o conteúdo, aplique a skill Content Format Rotator.

Analise o tema, objetivo, público, etapa de funil, CTA, canal, provas disponíveis, assets, recursos de produção e os formatos usados recentemente pela marca.

Não escolha automaticamente talking head para vídeo nem a estrutura tradicional de capa + explicação + lista + CTA para carrossel.

Primeiro defina o formato narrativo mais adequado. Depois escolha a melhor execução visual. Considere alternativas menos óbvias quando elas aumentarem clareza, retenção, prova, identificação ou intenção de ação.

Avalie formatos como notícia, fofoca, estudo fictício, use isso para isso, ranking, erro comum, mito x verdade, exercício, resposta, antes e depois, passo a passo, build in public, POV, case breakdown, comparativo, timeline, framework, guia de decisão e manifesto.

Para vídeo, considere talking head, tela verde, tela na tela, quadro branco, mindmap, tablet, UGC, stories nativo, narrado, reunião, clone, vlog, cinemático, texto na tela, cronômetro, screen recording e split screen.

Para carrossel, considere editorial, screenshot-first, data story, gráfico-first, timeline, comparativo, framework visual, documento anotado, interface walkthrough, photo essay, tipografia protagonista, case breakdown, checklist visual, notícia comentada, colagem de evidências, full bleed + análise, zoom progressivo e narrativa documental.

Escolha o formato com base no que melhora a ideia, não apenas para variar estética.

Evite repetição estrutural em relação aos conteúdos recentes.

Dê preferência a imagens, screenshots, dados, interfaces, fotos e documentos reais quando eles puderem funcionar como evidência ou parte do raciocínio.

Não invente dados, depoimentos, resultados, cases ou funcionalidades.

Depois de definir internamente a melhor combinação narrativa + execução, escreva a peça completa seguindo o briefing padrão da Refatorando.

Quando o roteiro tiver uma pessoa em cena:
- se houver duas aberturas, orientar que as duas sejam gravadas;
- se houver dois ou três fechamentos, orientar que todos sejam gravados;
- tratar essas versões como variações para teste criativo;
- nunca sugerir que a pessoa escolha apenas uma antes da gravação;
- na edição, usar apenas uma abertura e um fechamento por versão final.

No final, faça um QA de gancho/capa, clareza, progressão, retenção, visual, CTA, prova e risco de repetição. Se o formato escolhido não for claramente a melhor opção, reavalie antes de entregar."
